# Pet QR Tag Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Owners download and print a QR tag for each pet, with the Meoofy logo in the middle. Scanning it opens a public Meoofy page that says the pet's Discovery is off and gives finder tips, without revealing anything about the pet or owner.

**Architecture:**
- **Server:** one new `api.pet_tag_status(pet_id)` SECURITY DEFINER function, the only thing `anon` may call. It returns a single status word.
- **QR generation:** happens on the device. A pure function builds one SVG string (QR modules from `qrcode` at level H, the traced Meoofy mark in the centre, and a caption). That string feeds the on-screen preview (`SvgXml`), the PNG and PDF exports, and a decode test.
- **Public page:** a static `/t` route that reads `?p=` in the browser.

**Tech Stack:**
- Expo SDK 58 (Expo Router, RN 0.88, react-native-web, react-native-svg 15.16.0) and TanStack Query 5
- Supabase (Postgres, pgTAP)
- `qrcode`, `expo-print`, `expo-sharing`, `react-native-view-shot`
- dev-only: `potrace`, `pngjs`, `@resvg/resvg-js`, `jsqr`
- jest-expo + RNTL 14, vitest, Playwright

**Spec:** `docs/superpowers/specs/2026-10-26-pet-qr-tag-design.md`

**Precondition:** the owner's in-progress **Meoofy rename** must be committed to `main` before Task 1 starts. This plan uses its names: `@meoofy/core|api|ui|app`, `MeoofyClient`, `createMeoofyClient`, and `MEOOFY:<CODE>` server errors. The spec's line "the rest of the app keeps PawPin" is superseded by that rename. Nothing in this plan renames anything.

## Global Constraints

- **Package boundaries.** Packages are `@meoofy/app`, `@meoofy/ui`, `@meoofy/api`, `@meoofy/core`. Dependencies run only `app → api → core` and `app → ui`. Screens never import `@supabase/supabase-js`.
- **Dependencies.** Pin every new dependency exactly, with no `^`. Install Expo modules with `npx expo install` from `apps/app`.
- **Migrations (Ruling 15).** Shipped migrations are never edited; new SQL goes in a new migration. Every SECURITY DEFINER function sets `search_path = ''`, revokes all from `public`, and grants explicitly.
- **Privacy.** The public lookup returns only `'discovery_off'` or `'unavailable'`, never pet or owner data. Unknown, deleted, archived and `discovery_enabled = true` pets all return `'unavailable'` in this build. Scans write nothing: no audit row, no log table, no analytics.
- **Link format.** `${EXPO_PUBLIC_TAG_BASE_URL}/t?p=<pet id lowercased>`. The base must be `https://`, except `http://localhost` and `http://127.0.0.1`, which are allowed for development and E2E.
- **QR rendering.**
  - `qrcode` `errorCorrectionLevel: 'H'`, with a 4-module quiet zone.
  - Modules are drawn in brand blue `#2A52CF` (Task 4 confirms the exact value) on `#FFFFFF`.
  - The finder patterns keep the standard shape.
  - The logo backing is a white rounded square no wider than **22%** of the code's width.
- **Tag artwork.** It shows only the QR, the caption **"If I'm lost, scan me"**, and the tag domain. No pet name. Development builds without a base URL add a red band reading **"Test tag, not for printing"**.
- **Exports.**
  - A PNG of **1200×1200**.
  - A PDF with the tag at **25 mm, 30 mm and 38 mm**.
  - In production, both are disabled with "Tags will be ready soon" when no base URL is set.
- **Public page.**
  - **Brand and layout:** Meoofy brand and the `finder` flow tint. It sits outside the gate and the tabs.
  - **Head:** `<meta name="robots" content="noindex, nofollow">`, title "Meoofy".
  - **Copy:** exactly as in spec §3, with the four finder tips shown in every state.
- **Copy, layout and accessibility.**
  - Copy goes in one `copy.ts` per feature folder.
  - Tap targets are ≥ 44 pt.
  - Use `textStyle()` and never spread type tokens.
  - Text and background pairs come from token roles.
  - Status text never animates.
  - Decorative marks are hidden from assistive tech.
- **Commits.** Use Conventional Commits. Every message ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Uppercase or messy ids in links.** A tag scanned from a link with an uppercase UUID, or with `p` repeated (`?p=A&p=B`), still resolves. `parseTagParam` lowercases, takes the first value of an array, and rejects anything else. *Test: Task 2.*
2. **The smallest printed size still scans.** At the 25 mm size (about 295 px at 300 dpi), the tag with its logo decodes to the exact link. *Test: Task 5, the scan proof at 295 px.*
3. **The owner scans their own tag while signed in.** They see the same public page, with no redirect into the tabs, and their session and cache stay untouched. *Test: Task 7.*
4. **The tag screen opened offline.** It renders the QR from the cached pet and keeps the exports usable, since generation needs no network. *Test: Task 6.*
5. **A base URL with a trailing slash or path, or misconfigured.** `https://meoofy.com/` gives `https://meoofy.com/t?p=…`. A non-https production value counts as unset, and downloads are disabled rather than printing a broken link. *Tests: Task 2 and Task 5.*
